# 2026-08-14 工作日志

## 体温 vitalsignNVal2 字段未传问题分析

### 问题描述
调整了体温回传逻辑，要求当 vitalsignNVal1 >= 38.5 时查询1小时内的复测值填入 vitalsignNVal2，但日志显示该字段一直没有传。

### 根因分析
系统存在**新旧两条并行路径**，实际体温回传走的是旧路径，而 vitalsignNVal2 逻辑只在新路径中实现：

1. **旧路径（实际发送体温数据）**: `ScheduleTask.scheduleVital()` → `DataService.selectVitalSignsAfterLastTime()` → `HandleService.handle()` → `TemperatureServiceImpl.special()`(空方法) → `ReturnService.uploadInfo()` → `ReturnService.tableToData()`
   - `ReturnService.tableToData()` 处理 param_T 时只设置 vitalsignNVal1 和 vitalsignSVal1("腋温")，**不设置 vitalsignNVal2**
   - `TemperatureServiceImpl.special()` 是空实现，没有复测逻辑

2. **新路径（有 vitalsignNVal2 逻辑但未生效）**: `VitalSignScanTask.execute()` → `processVitalSign("param_T")` → `TemperatureHandler.handle()` → `PushService`
   - `TemperatureHandler.handle()` 正确实现了复测逻辑（>=38.5 查1小时内复测值）
   - 但 `VitalSignScanTask` 查询 bedside 时加了 `valid: true` 条件，旧路径不加此条件
   - 日志显示 param_T "未找到bedside记录"，说明 bedside 中该记录可能 valid != true
   - 新路径从未被触发处理体温数据

3. 两条路径使用相同 cron（每分钟），旧路径先执行（13:29:09）找到并回传了体温，新路径后执行（13:29:10）查不到记录

### 关键文件
- `ReturnService.java` - 旧路径回传，tableToData() 中 param_T 分支无 vitalsignNVal2
- `TemperatureHandler.java` - 新路径处理器，有完整的复测逻辑
- `VitalSignScanTask.java` - 新路径扫描任务，查询加了 valid:true
- `TemperatureServiceImpl.java` - 旧路径 special() 空实现
- `MongoDao.selectVitalSignsAfterLastTime()` - 旧路径查询，不过滤 valid
